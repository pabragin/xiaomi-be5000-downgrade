# Xiaomi BE5000: раздача штатной прошивки 1.0.53 по Ethernet

English instructions: [README.en.md](README.en.md).

Этот репозиторий содержит DHCP/TFTP-сервер для **macOS, Linux и Windows**. Он передаёт официальную
подписанную прошивку Xiaomi загрузчику Xiaomi BE5000 в режиме восстановления. Скрипт
сам не записывает флеш-память и **не обходит проверку отката**: получение 100%
по TFTP ещё не доказывает, что версия изменилась. На другом экземпляре или
версии загрузчика результат может отличаться. Нужен Python 3.8 или новее.
Реальная передача на Xiaomi BE5000 проверена с macOS; Linux и Windows пока проверены
только на уровне кода.

## Кратко: последовательность отката

Это порядок, который сработал на одном Xiaomi BE5000. Скрипт на каждом цикле ниже
передаёт именно прошивку **1.0.53**.

1. Подготовьте соединение и запустите `recover.py` по инструкции ниже.
   Кабель подключите к первому порту Xiaomi BE5000 (LAN1).
2. Включите роутер с зажатым Reset, отпустите кнопку, когда индикатор начнёт
   мигать жёлтым. Дождитесь `TFTP transfer complete` и 100% передачи.
3. Если после передачи индикатор не горит, подождите примерно **10 секунд**
   и отключите питание роутера.
4. Снова запустите режим восстановления с Reset и дождитесь полной передачи
   1.0.53. Если индикатор по-прежнему выключен, подождите примерно
   **20 секунд после 100%** и снова отключите питание.
5. Запустите восстановление с Reset ещё раз, дождитесь полной передачи 1.0.53
   и оставьте роутер включённым для загрузки. При успешном откате индикатор
   может не загореться жёлтым сразу. Проверьте `romversion` через API ниже.

Отключение питания после TFTP — рискованный приём из личного опыта, а не
гарантированная процедура: роутер может в это время проверять или записывать
образ. Возможен отказ загрузки и необходимость UART/программатора. Идея
последовательности вдохновлена [этой темой на форуме](https://www.right.com.cn/forum/thread-8470335-1-1.html).

## Файлы

- `recover.py` — сервер DHCP/TFTP, который обслуживает только один клиент
  восстановления и только образ 1.0.53.
- `POST.md` / `POST.en.md` — краткий отчёт о реальном откате с 1.0.91
  на русском и английском.
- `LOG_EXAMPLE.md` — обезличенный фрагмент журнала нашей попытки.
- Образ прошивки не включён. Если файла нет рядом со скриптом, тот сам
  скачает его напрямую с сервера Xiaomi:
  <https://cdn.cnbj1.fds.api.mi-img.com/xiaoqiang/rom/rd18/miwifi_rd18_firmware_6c571_1.0.53.bin>

Размер образа: `31 069 192` байта. SHA-256:
`cdc567abd5b9d4ff10adb02ee9592575640e5607135a4588f05e7bdc2cab17d0`.
Скрипт сверяет оба значения до открытия серверов. Можно скачать и проверить
образ заранее без запуска DHCP/TFTP: `python3 recover.py --download-only`
(на Windows: `py -3 recover.py --download-only`). После загрузки интернет
скрипту больше не нужен.

## Подготовка

1. Скачайте репозиторий и перейдите в его папку:

   ```sh
   git clone https://github.com/pabragin/xiaomi-be5000-downgrade.git
   cd xiaomi-be5000-downgrade
   ```

   На Windows можно вместо `git clone` скачать ZIP через кнопку **Code** на
   GitHub и распаковать его.
2. Соедините компьютер кабелем напрямую с **первым Ethernet-портом Xiaomi BE5000 (LAN1)** —
   именно он использовался при успешной попытке. Отключите WAN и остальные
   устройства от роутера. Для TFTP используется именно проводное соединение.
3. Убедитесь, что другие DHCP/TFTP-службы не занимают UDP-порты 67 и 69.
   На macOS/Linux это можно проверить командой
   `sudo lsof -nP -iUDP:67 -iUDP:69`. При необходимости выключите «Общий
   интернет» или другую службу, использующую эти порты.

### macOS

Узнайте имя проводного интерфейса: `networksetup -listallhardwareports`.
У автора USB-Ethernet адаптер имел имя `en8`. Запуск:

```sh
sudo /usr/bin/python3 recover.py --interface en8
```

### Linux

Узнайте имя интерфейса: `ip -br link`. Например, для `enp3s0`:

```sh
sudo python3 recover.py --interface enp3s0
```

Скрипт временно добавляет `192.168.31.100/24` через утилиту `ip` и удаляет
его при остановке.

### Windows (экспериментально)

Нужен Python 3.8+ и PowerShell от имени администратора. Сначала, пока
доступен интернет, скачайте образ:

```powershell
py -3 recover.py --download-only
```

Задайте Ethernet-адаптеру вручную IPv4 `192.168.31.100`, маску
`255.255.255.0`, без шлюза. После этого отключите Wi-Fi и другие сетевые
адаптеры, чтобы DHCP-ответ ушёл через кабель к роутеру. Узнайте имя адаптера
через `Get-NetAdapter` и запустите, подставив его имя:

```powershell
py -3 recover.py --interface "Ethernet"
```

Разрешите Python доступ к частной сети, если появится запрос брандмауэра.
Windows-режим ещё не проверен на реальном Xiaomi BE5000; в отличие от macOS/Linux,
скрипт не создаёт и не удаляет адрес адаптера автоматически.

## Восстановление и проверка

1. Запустите сервер командой для своей системы из раздела выше. Если образа
   рядом нет, на macOS/Linux он автоматически загрузится до запуска серверов.
2. Дождитесь строк `TFTP listening` и `DHCP listening`.
3. Отключите питание роутера. Удерживая Reset, включите питание. Отпустите Reset,
   когда индикатор начнёт мигать жёлтым. Дождитесь `DHCP DISCOVER`, `TFTP RRQ`
   и прогресса до 100%. Повторные DHCP-запросы без завершённой передачи
   означают, что образ не получен целиком.
4. После `TFTP transfer complete` обычно нужно оставить роутер включённым и
   дождаться его реакции: передача файла ещё не означает успешную запись.
   Особенности нашего случая с погасшим индикатором описаны ниже.
5. После загрузки проверьте версию в веб-интерфейсе или через локальный API:

   ```sh
   curl -fsS 'http://192.168.31.1/cgi-bin/luci/api/xqsystem/init_info'
   ```

   Нужные поля: `romversion` должно быть `1.0.53`. Внутреннее поле `hardware` может показывать `RD18`.
6. Завершите сервер `Ctrl+C`. На macOS/Linux он удалит временный адрес,
   который сам добавил. На Windows верните обычные настройки IPv4 вручную.

Скрипт автоматически распознаёт загрузчик по DHCP-полю `tclinux.bin` и
запоминает его MAC-адрес. При необходимости его можно задать через
`--router-mac MAC_ЗАГРУЗЧИКА`: подставьте шесть шестнадцатеричных пар,
разделённых двоеточиями, из пакета загрузчика, а не адрес другого устройства.
Скрипт выводит обнаруженный MAC в журнал; перед публикацией журнала скройте
этот адрес.

## Что произошло при откате с 1.0.91

При первой передаче TFTP дошёл до 100%, но версия 1.0.91 сохранилась.
В следующих попытках роутер **полностью получал образ по TFTP**, а индикатор
после передачи оставался выключенным. В нашем случае в этом состоянии
несколько раз отключали питание: ориентировочно через 10 секунд после
завершения TFTP, затем при очередной попытке — примерно через 20 секунд.
После этого снова запустили восстановление с зажатым Reset и образом 1.0.53,
дали роутеру загрузиться и проверили: API показал `romversion: 1.0.53`.

Это наблюдение, а не проверенная процедура: точное число попыток и моменты
отключения не фиксировались. Погасший индикатор **не позволяет определить**,
проверяет ли роутер образ или записывает его во флеш. Намеренное отключение
питания даже после окончания TFTP может оставить роутер без загрузки; для
ремонта может потребоваться UART или программатор. Один только лог `100%`
не подтверждает откат.
