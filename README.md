# Xiaomi BE5000: даунгрейд штатной прошивки до 1.0.53 по Ethernet

English instructions: [README.en.md](README.en.md).

Этот репозиторий содержит DHCP/TFTP-сервер для **macOS, Linux и Windows**.
Он передаёт официальную подписанную прошивку загрузчику Xiaomi BE5000 в
режиме восстановления. Скрипт не пишет флеш-память напрямую и не обходит
проверку отката. Нужен Python 3.8 или новее. Работа сервера проверена на
реальном BE5000 под macOS; Linux и Windows проверены только на уровне кода.

## Кратко: последовательность даунгрейда

Порядок основан на сообщении владельца BE5000 об успешном даунгрейде
1.0.88 → 1.0.53 на [4PDA](https://4pda.to/forum/index.php?showtopic=1088946&st=2240)
и на [подробном описании метода для BE5000](https://www.right.com.cn/forum/thread-8470335-1-1.html).
Автор подробного описания сначала обновил роутер с 1.0.87 до 1.0.91; там же
приведены наблюдения индикатора и примерные интервалы.
Способ прерывает две попытки установки 1.0.91, чтобы повредить обе системные
копии, а затем устанавливает 1.0.53 через штатный recovery. Прерывание записи
рискованно и может привести к необходимости UART или программатора.

1. Подготовьте кабель и компьютер по инструкции ниже. Подключите кабель к
   **первому Ethernet-порту (LAN1)**. Если установлена версия ниже 1.0.91,
   сначала обновите роутер штатным способом до официальной 1.0.91. Для раздачи
   выберите один вариант:
   `recover.py` (macOS/Linux/Windows) либо официальный
   [MiWiFi Repair Tool](https://cdn.cnbj1.fds.api.mi-img.com/xiaoqiang/tools/MIWIFIRepairTool.x86.zip)
   (Windows). Не запускайте их одновременно. При установленной 1.0.91 выберите
   образ **1.0.91**.
2. Запустите выбранный сервер/инструмент и укажите файл 1.0.91. Включите роутер,
   удерживая Reset; отпустите кнопку после начала жёлтого мигания. Дождитесь
   100% передачи. Для `recover.py` также дождитесь `TFTP transfer complete`.
3. В описании именно BE5000 автор сообщает примерно о **20 секундах** после
   первой передачи до отключения питания. Затем снова запустите recovery с
   Reset и тем же образом 1.0.91, дождитесь 100%.
4. После второй передачи автор отключил питание примерно через **10 секунд**.
   Интервалы приблизительные, это не универсальные таймеры.
5. Завершите текущую попытку и смените образ на 1.0.53. Для `recover.py`
   остановите и перезапустите сервер командой
   `sudo python3 recover.py --interface ИНТЕРФЕЙС --firmware 1.0.53`; в MiWiFi
   Repair Tool выберите 1.0.53. Запустите recovery с Reset, дождитесь 100% и
   дайте роутеру завершить установку и загрузиться. Проверьте
   `romversion: 1.0.53` через API.
6. Если после 100% передачи **1.0.53** индикатор сразу загорается постоянным
   жёлтым, очистка системных разделов, вероятно, не завершилась. Вернитесь к
   шагам 2–4 с образом 1.0.91, затем снова выполните шаг 5.

Важное различие: 100% означает, что файл передан по TFTP, но не подтверждает
запись или очистку разделов. Состояние индикатора и интервалы отключения —
наблюдения и рекомендации из конкретных попыток, а не универсальная гарантия.
Не отключайте питание вне описанных циклов.

MiWiFi Repair Tool — штатная Windows-утилита Xiaomi, которая сама обслуживает
recovery-раздачу. На macOS и Linux используйте `recover.py` или другой DHCP/TFTP
сервер, настроенный под параметры recovery. Для обоих вариантов нужен тот же
официальный образ; последовательность циклов одинакова.

## Файлы

- `recover.py` — сервер DHCP/TFTP, который обслуживает только один клиент
  восстановления и выбранный образ 1.0.53 или 1.0.91.
- `POST.md` / `POST.en.md` — краткий отчёт о реальном откате с 1.0.91
  на русском и английском.
- `LOG_EXAMPLE.md` — обезличенный фрагмент журнала нашей попытки.
- Образ прошивки не включён. Если файла нет рядом со скриптом, тот сам
  скачает его напрямую с сервера Xiaomi. Для очистительного этапа нужна
  [версия 1.0.91](https://cdn.cnbj1.fds.api.mi-img.com/xiaoqiang/rom/rd18/miwifi_rd18_firmware_05f43_1.0.91.bin),
  для отката — [версия 1.0.53](https://cdn.cnbj1.fds.api.mi-img.com/xiaoqiang/rom/rd18/miwifi_rd18_firmware_6c571_1.0.53.bin).
  Скрипт проверяет размер и SHA-256 каждого образа перед запуском серверов.
  Заранее скачать образ можно с `python3 recover.py --firmware 1.0.91 --download-only`
  или `python3 recover.py --firmware 1.0.53 --download-only` (Windows: `py -3`).

## Подготовка

### Вариант без нашего скрипта: MiWiFi Repair Tool

Скачайте [официальный MiWiFi Repair Tool от Xiaomi](https://cdn.cnbj1.fds.api.mi-img.com/xiaoqiang/tools/MIWIFIRepairTool.x86.zip)
и распакуйте его на Windows. Подключите компьютер к LAN1, задайте Ethernet-
адаптеру адрес `192.168.31.100` и маску `255.255.255.0`, отключите Wi-Fi.
В программе выберите нужный официальный образ и запустите recovery. В двух
циклах очистки выберите 1.0.91, затем в отдельной попытке выберите 1.0.53.
Утилита заменяет наш скрипт только как средство раздачи файла. Эта комбинация
инструмента и способа описана в источниках выше, но отдельно автором
репозитория не проверялась.

1. Скачайте репозиторий и перейдите в его папку:

   ```sh
   git clone https://github.com/pabragin/xiaomi-be5000-downgrade.git
   cd xiaomi-be5000-downgrade
   ```

   На Windows можно вместо `git clone` скачать ZIP через кнопку **Code** на
   GitHub и распаковать его.
2. Соедините компьютер кабелем напрямую с **первым Ethernet-портом Xiaomi BE5000 (LAN1)** —
   именно он использовался при успешной попытке. Отключите WAN и остальные
   устройства от роутера. Для TFTP используется именно проводное соединение.
3. Убедитесь, что другие DHCP/TFTP-службы не занимают UDP-порты 67 и 69.
   На macOS/Linux это можно проверить командой
   `sudo lsof -nP -iUDP:67 -iUDP:69`. При необходимости выключите «Общий
   интернет» или другую службу, использующую эти порты.

### macOS

Узнайте имя проводного интерфейса: `networksetup -listallhardwareports`.
У автора USB-Ethernet адаптер имел имя `en8`. Запуск:

```sh
sudo /usr/bin/python3 recover.py --interface en8 --firmware 1.0.91
```

### Linux

Узнайте имя интерфейса: `ip -br link`. Например, для `enp3s0`:

```sh
sudo python3 recover.py --interface enp3s0 --firmware 1.0.91
```

Скрипт временно добавляет `192.168.31.100/24` через утилиту `ip` и удаляет
его при остановке.

### Windows (экспериментально)

Нужен Python 3.8+ и PowerShell от имени администратора. Сначала, пока
доступен интернет, скачайте образ:

```powershell
py -3 recover.py --firmware 1.0.91 --download-only
py -3 recover.py --firmware 1.0.53 --download-only
```

Задайте Ethernet-адаптеру вручную IPv4 `192.168.31.100`, маску
`255.255.255.0`, без шлюза. После этого отключите Wi-Fi и другие сетевые
адаптеры, чтобы DHCP-ответ ушёл через кабель к роутеру. Узнайте имя адаптера
через `Get-NetAdapter` и запустите, подставив его имя:

```powershell
py -3 recover.py --interface "Ethernet" --firmware 1.0.91
```

Разрешите Python доступ к частной сети, если появится запрос брандмауэра.
Windows-режим ещё не проверен на реальном Xiaomi BE5000; в отличие от macOS/Linux,
скрипт не создаёт и не удаляет адрес адаптера автоматически.

## Запуск recovery и проверка

Для очистительного этапа запускайте сервер с `--firmware 1.0.91`; после него
остановите сервер и перезапустите с `--firmware 1.0.53`. Пример для Mac:

```sh
sudo /usr/bin/python3 recover.py --interface en8 --firmware 1.0.91
sudo /usr/bin/python3 recover.py --interface en8 --firmware 1.0.53
```

Каждый раз дождитесь `TFTP listening` и `DHCP listening`, затем выключите
роутер и включите с зажатым Reset. Отпустите Reset при жёлтом мигании.
Дождитесь `TFTP transfer complete` и 100%. В очистительном цикле выполните
отключения питания по шагам 2–4 выше. Если при попытке установки 1.0.53 после
100% появляется постоянный жёлтый свет, снова выполните очистительные циклы
с 1.0.91, затем повторите установку 1.0.53.

Проверьте результат в веб-интерфейсе или через локальный API:

```sh
curl -fsS 'http://192.168.31.1/cgi-bin/luci/api/xqsystem/init_info'
```

Убедитесь, что `romversion` показывает `1.0.53`. Внутреннее поле `hardware`
может показывать платформенный идентификатор `RD18`. Завершите сервер через
`Ctrl+C`; на macOS/Linux временный адрес будет удалён автоматически.

Скрипт автоматически распознаёт загрузчик по DHCP-полю `tclinux.bin` и
запоминает его MAC-адрес. При необходимости его можно задать через
`--router-mac MAC_ЗАГРУЗЧИКА`: подставьте шесть шестнадцатеричных пар,
разделённых двоеточиями, из пакета загрузчика, а не адрес другого устройства.
Скрипт выводит обнаруженный MAC в журнал; перед публикацией журнала скройте
этот адрес.
